# SITC — SITC

Сайт локального IT-сообщества. Публичные страницы собираются YiiPress в статические файлы. Для будущей интерактивной части используется Yii 3; в разработке PHP-FPM, Nginx и PostgreSQL запускаются через Docker Compose.

## Запуск для разработки

Необходимы Docker с работающим сервером, Docker Compose и Make.

```sh
make init
```

Откройте http://localhost:8080. Порты и учётные данные локальной базы задаются в `.env`. PostgreSQL доступен на `localhost:5432`; из контейнера приложения — на `db:5432`. Данные хранятся в томе `postgres_data`. Настройки `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` передаются контейнеру приложения; подключение базы к коду и миграции предстоит добавить при реализации первой функциональности.

```sh
make site-build                 # пересобрать страницы после изменения content/
make help                       # все команды
make up                         # запустить проект
make down                       # остановить контейнеры, сохранив данные
make logs ARGS="app nginx"      # логи выбранных сервисов
make shell                      # shell приложения
make yii ARGS="--help"          # команды Yii
make composer ARGS="show"       # команды Composer
make test                       # тесты Codeception
```

Конфигурация предназначена только для разработки: отладка включена, пароль базы тестовый. Профили, авторизация, задания и остальные функции пока не реализованы.

Шаблон приложения: [yiisoft/app](https://github.com/yiisoft/app), лицензия BSD-3-Clause; лицензия проекта — в файле LICENSE.

## Статические страницы и размещение

Контент и настройки YiiPress находятся в `content/`, результат сборки — в `output/`. `make site-build` запускает отдельный контейнер только на время сборки; статические файлы затем отдаёт Nginx. В сборке используется nightly-образ YiiPress: перед публикацией следует выбрать и закрепить проверенную версию через `YIIPRESS_IMAGE` в `.env`. Образ рассчитан на Linux amd64; на Apple Silicon Docker использует эмуляцию.

Для публикации задайте реальный адрес сайта в `content/config.yaml` (`base_url`) и соберите страницы. На хостинге Docker и YiiPress не нужны: разместите содержимое `output/` как статический сайт, а PHP-приложение с зависимостями — вне публичного каталога. Настройте веб-сервер так, чтобы существующие статические файлы отдавались напрямую, `/api/` и остальные отсутствующие пути передавались в `public/index.php` через PHP-FPM. Конфигурация `docker/nginx/default.conf` показывает маршрутизацию для разработки; пути и FastCGI-сокет на хостинге будут другими. Не размещайте корень проекта в публичной директории.

При изменении статического контента повторно выполните `make site-build` и загрузите результат. Если домен сайта ещё не выбран, `http://localhost:8080` в `base_url` подходит только для локальной разработки: он используется в абсолютных ссылках и sitemap. Профили, вход и другие интерактивные возможности будут реализованы в PHP-бэкенде; сейчас API-маршрутов нет.
